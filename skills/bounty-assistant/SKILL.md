# 悬赏参赛助手

把可核实的悬赏转成符合征集要求、可由用户审阅的作品和可追溯的报名记录。优先做好中文口号、命名、短文案；其他任务根据实际交付能力单独评估。

## 先判断这次要做什么

- **找项目**：检索、去重、核验和排序，更新候选；不用同时创作全部项目或报名。
- **做作品**：在选定项目及规则范围内研究、创作、审稿，准备完整材料。
- **投稿**：按本次有效授权发送确切版本，核对结果并记录。
- **查进度**：只读取有关项目的邮件、公告和记录，区分已发送、已受理、获奖与到账。
- **暂停/恢复**：暂停后保留资料，停止后续参赛操作；恢复先刷新日期及规则。“继续看看、先筛选、不发”只授权查看/筛选，不把 `campaign_paused` 改为 false，也不恢复创作或提交；仅执行用户此次明确恢复的阶段。

日常查找默认关注国内公开的现金悬赏；若用户指定地域、奖品或任务类型，以用户为准。用真实奖金、预计准备成本、规则适配度、来源质量和剩余时间解释排序，不编造获奖概率或收入预测。

## 读取持久记录

如本技能目录存在 `config.local.json`，读取其中 `state_directory`；用户指定的数据目录优先。在该目录读取 `profile.json` 与 `ledger.json`。配置缺失时，先查当前项目已存在的悬赏 LIST；新建数据目录前不要忽略旧的提交历史。

首次使用且没有旧记录时，按 [references/records.md](references/records.md) 初始化空台账，默认放在当前工作目录的 `outputs/bounty-data`。查项目无需先录入全部个人信息。公开安装包不含任何个人配置或参赛记录。

身份资料、参赛偏好及确认要求留在个人数据目录，不写进通用技能正文。用户的补充信息只用于其指定用途，不视为新的投稿授权。缺少某个必填项时先完成其余准备，不推断证件号、通讯地址或所属地区。

匹配项目或收集资料时读取 [references/profile-tiers.md](references/profile-tiers.md)：一级基础联系资料、二级背景资料、三级实名/证明资料，领奖财税资料单独在获奖后按需收集。等级用于解释资料负担；资格、作品难度和投稿授权分别判断。先匹配已有资料，再对选中项目合并询问缺项，不要求填满整级。表单未读全时不得显示“资料已齐”。

记录和导入规则见 [references/records.md](references/records.md)，更新台账时读取。已有邮件、作品或名单必须先读后改。日期检查可运行：

```bash
python3 <本技能目录>/scripts/ledger_status.py --ledger <数据目录>/ledger.json
```

此脚本只检查本地数据并导出时间状态，不联网、不发信，也不能证明活动今天仍在收稿。截止已到不能抹掉历史已提交、获奖等状态。读取 `campaign_paused`；创建或安装本技能不解除已有暂停状态。

## 搜集与核验

多来源公开搜索，主办官网/认证账号优先，可靠媒体其次，征集聚合站用于发现线索。不承诺互联网全覆盖；登录限制、验证页和打不开的规则如实记录，不绕过访问控制。

每项至少辨清：活动及年份、主办方、实际参赛类别、投稿截止及地区时区、报名资格、作品格式/字数/件数、奖励及兑现条件、投稿入口、AI与原创条款、版权安排、来源和核验时间。

关键判断：

- 以公告正文的投稿时间为准，不能用网页更新时间、比赛举办时间、奖品有效期或其他类别截止日替代。日期只写月日且年份不清时，保留“待核验”。
- 只写截止日期而没有时刻时，不编造官方截止时间；到截止当天显示“具体时刻待核”，提交前查明。显式24:00才按当地次日零点理解。
- 分开记录现金、购物卡、奖品、总奖金池、税前税后和奖项可空缺。优胜奖与入围奖是否叠加按原文，不自行加总。
- 区分主办一手、媒体、转载；同源转载不构成独立确认。打不开官方原文时，可交付明确标记的候选，不能升级为“官方已核”。正式投稿前核对权威报名渠道及必需规则。
- AI规则保留 `allowed / prohibited / unspecified / unknown` 四种状态。明确禁用AI的项目不进入AI代创投稿流程；未提及不等于允许。读不到细则记 unknown；条款冲突时先解决冲突。
- 搜索前读旧记录，按主办、活动年份、类别及原文去重；不能把同活动不同转载当成多个机会。
- 恢复旧清单或临近提交时重新查原公告及后续延期/取消通知。原截止已到只表示“按记录截止已到”，查到延期原文后才更新。

找不到足够可靠的项目就报告实际数量与待核线索，不为凑数塞入已过期、重复或不符合条件的项目。以简表交付名称、截止、奖励、任务量、资料级别、具体缺项、渠道和来源强度；先推荐已有资料足够且规则适配的项目。

## 创作与提交

创作、审阅和发送细节见 [references/creation-and-submission.md](references/creation-and-submission.md)，在进入这些阶段时读取。

默认先把材料做成可审阅版本。是否需要逐次确认取决于用户已明确的要求及本次授权；已有批准的确切版本不重复索要同一确认。个人配置要求最终正文确认时，展示收件方、主题、完整正文和附件；仅补资料、选项目或说“继续准备”不算确认发送。

发出后用工具返回的邮件ID/提交凭证复核。响应不确定时先查实际状态，不盲目重发。严守件数及每人投稿次数，已投项目默认只查进度。

## 投稿后的跟进

提交后为项目建立回执、公示、领奖与到账记录，读取 [references/follow-up.md](references/follow-up.md)。把官方公示日期、助手建议检查日、领奖截止分开；每次检查保留来源、最近成功时间、下次检查和失败状态。发现获奖须匹配作品或报名编号，不能仅凭同名。未发现公示不等于落选。

用户明确要求持续监测后，使用可用自动化工具创建或更新一个覆盖已报名项目的定时任务，并核对工具返回的启用状态；仅写入跟进计划不等于已经启用提醒。停止新投稿和停止监测分开记录；明确“全停”立即停止所有相关自动化，不能用跟进绕过暂停。

## 运行范围与输出

技能是工作流程，需要当前可用的搜索、邮箱、浏览器和文件工具配合；工具缺失时说明可完成到哪一步，不能虚报调用或提交成功。优先连接器/API，必要时用浏览器；不要对整个邮箱做与项目无关的扫描。

用户要求周期搜集或结果监测时再创建/更新定时任务，保留其通知偏好；未提出定时请求时只执行当前任务。任何重试都止于本次授权，暂停指令立即生效。

结束时报告实际完成项、未解决项、是否已对外提交和更新后的 LIST。记录可靠项目数、准备时间、实际提交、受理、获奖及到账证据，供之后选择任务类型；不把发送成功当成报名受理或收益。
