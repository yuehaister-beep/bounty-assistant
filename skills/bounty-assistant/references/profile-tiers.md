# 分级资料与按需补齐

资料等级描述主办方要求的资料负担，不代表作品难度、用户能力或获奖概率。先提供轻量入口；用户不提供更多资料时，继续匹配已有资料可完成的项目。

| 等级/阶段 | 常见资料 | 收集时机 |
|---|---|---|
| 一级·轻 | 姓名/署名、邮箱、手机号 | 初次使用可先录入实际所需项 |
| 二级·中 | 单位、所在地区、籍贯、简介 | 选中项目确有要求时补充 |
| 三级·实名/证明 | 详细地址、证件号或文件、本人签名、资格证明；企业申请需主体证明与授权 | 核验项目及要求后逐项准备 |
| 领奖阶段 | 收款、税务等资料 | 核实获奖与收款渠道后按需准备，不作为普通投稿的升级条件 |

每级是字段集合而非整套必填问卷。需要“姓名+单位”的项目不要求用户先提供地区、籍贯。提供工作单位不等于以企业名义参赛，也不能推断已有企业授权。作品制作量另列为短口号、说明文、设计附件等。

## 从规则生成资料清单

为每个项目记录 `requirements.personal_data`；字数、作品附件、资格及版权继续使用原 requirements 等字段。示例：

```json
{
  "completeness": "known",
  "fields": [
    {"key": "name", "phase": "submission", "required": true},
    {"key": "phone", "phase": "submission", "required": true}
  ],
  "any_of": [
    {"keys": ["hometown", "unit"], "phase": "submission", "required": true}
  ],
  "evidence_urls": [],
  "basis": "existing_record",
  "source_verified_at": null
}
```

- `completeness` 只表示资料字段是否已看全：known / partial / unknown；不表示来源权威、规则今天有效或允许AI。表单、报名表尚未打开时保持 partial/unknown；不把必填项的空列表解释成“无需资料”。
- 字段 `required` 区分必填和选填；`phase` 分 submission（投稿）、claim（领奖）。有条件的要求须先判断条件，条件未明用 partial 并记录问题，不提前把领奖字段变成报名缺项。
- “单位或籍贯”是一个 any_of 组；满足其一即可。含糊的“联系方式”可暂记录 phone/email 备选并说明原文；正式表单指定手机号时须据实更新。
- 出处存原公告URL和原核验日期。旧LIST导入使用 existing_record；整理日期不能冒充再次联网核验。

当前标准键：一级 name/email/phone；二级 unit/region/hometown/bio；三级 postal_address/id_number/id_document/signature/qualification_document/company_license/company_authorization；领奖 bank_account/tax_information。新字段先明确含义及负担，不默认归为一级。

## 匹配与询问

从用户资料中找已有值，对照当前项目的必填字段；同时保留三个判断：**已有资料是否够用、资料规则是否读全、实际使用是否获授权**。资格、截止、来源与AI条款另外检查，不能由“资料齐全”推出“可直接投”。

只读匹配器：

```bash
python3 <本技能目录>/scripts/profile_readiness.py --profile <数据目录>/profile.json --ledger <数据目录>/ledger.json
```

脚本只输出字段名称、等级与缺项，不回显姓名、号码、邮箱或证件内容。claim 字段不阻挡 submission；脚本不验证证件真实性、文件是否仍可用或用户授权，也不自动填表。等级未知和表单未读全时必须继续核对。

向用户一次展示所选项目的缺项并按字段去重，例如：“甲、乙两项均需所在地区；丙另需单位。已提供的姓名、电话、邮箱无需重填。”说明每个新增项用于哪个项目、是否必需。没有选中的项目不为了预备将来收集全套资料；用户拒绝补项则保留为待补或改荐其他项目。

profile 保留既有字段以兼容旧记录，可增加 `field_metadata`，按字段记录用户提供/更正时间、允许用途与失效时间。只根据真实用户输入写入，不伪造确认时间或默认长期授权。已有普通资料在用户授权目的内复用；每次投稿只放主办方所需项，仍遵守用户的最终审阅要求。更正字段时提醒尚未发送的关联材料需要同步；不得改写已发送的历史正文。

## 敏感资料

证件、签名、银行信息不要求预先存入通用资料库；按具体项目临时提供或由用户在可信官方入口填写。需保存时按用户指定的本地范围记录文件引用，普通LIST仅写“已提供/待提供”、用途和阶段，不展开内容，不假设本地JSON已加密。签名由本人完成，不能生成冒充本人签署的文件。用户同意参加某一征集不自动授权把资料用于其他主办方。
